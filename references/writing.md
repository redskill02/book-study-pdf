# 챕터 HTML 작성 규격

## 파일 구성

작업 폴더 하나에 전부 넣는다.

```
book_<약칭>/
  style.css        ← assets/style.css 복사
  *.py             ← scripts/ 전부 복사 (build.py · imgcheck.py · _chain.py … 는 자기 폴더에서 돈다)
  book.json        ← templates/book.json 을 채운다 (mode · figures · titles · chapter_files)
  _GATE.md         ← templates/_GATE.md — 판정 · 오프셋 · 도판 분류 · 권 구성 · 권별 기록
  _src/src1.pdf    ← 원본 (분권이면 src2 …) · _src300/ 300dpi 사본 · _mineru_in/ MinerU 입력 · out1/ MinerU 출력 · crops/ 크롭
  _front.html      ← 표지 + 차례 + 계획표 + "이 학습노트에 대하여" (templates/front.html)
  ch01.html ... chNN.html  ← 권 (templates/chapter.html)
  ch99.html        ← 총정리 · 종합시험
  pdf/             ← 자동 생성
```

각 챕터 HTML 골격:

```html
<!doctype html>
<html lang="ko"><head><meta charset="utf-8">
<title>SECTION I — ...</title>
<link rel="stylesheet" href="style.css">
</head><body>
<div class="cover">
  <div class="sec">SECTION I</div>
  <h1>여기서 시작</h1>
  <div class="lead">이 챕터에서 답하는 질문 …</div>
  <div class="meta">도표 6 · 만화 4컷 2편 · 예시 3 · 시험문제 32</div>
</div>
...
</body></html>
```

`.meta` 는 **정확히 이 형식**이어야 `stats` 가 대조한다: `도표 %d · 만화 4컷 %d편 · 예시 %d · 시험문제 %d`
(도표 = `<figure>` − 만화 · 만화 = `4컷 만화로 재구성` 문자열 수 · 예시 = `.kr-case` · 문항 = `class="q"`).
`<h1>` 은 **600자 이내** — 넘으면 `.meta` 가 2쪽으로 밀린다. `.sec` 에 권 번호 · 장 제목 · 책 쪽 범위를 적는다.

## 모드별 집필법

`book.json`의 `"mode"` 에 따라 **본문 정리 방식과 예시 처리만** 달라진다.
나머지(도표 재작도·만화·시험문제·검증)는 완전히 동일하다.

### `translate` — 영어 원서

- 원문 구조(헤딩·목록·표)를 **유지**하며 한국어로 옮긴다
- 용어는 **한국어 + 괄호 원어**: `고객 자금 조달 획득(Client Financed Acquisition)`
- 저자 특유의 표현은 **인용으로 살린다.** 매끄럽게 다듬다가 힘을 잃는 문장이 있다
- 미국 맥락 사례(체육관 프랜차이즈, 달러 금액)는 **한국 사례로 대체**한다

### `digest` — 한국어 책

번역이 필요 없다는 이유로 **"그대로 옮기면" 안 된다.** 그러면 원본을 읽는 것과 같다.
목표는 **원본보다 쉬운 자료**다. 아래 넷을 한다.

| 할 일 | 구체적으로 |
|---|---|
| **문장을 짧게 끊는다** | 한 문장에 주장 하나. 원본의 긴 만연체를 나눈다 |
| **전문용어를 풀어 쓴다** | 처음 나올 때 한 줄로 설명하고 괄호로 원어 병기. `.term` 표에도 모은다 |
| **구조를 드러낸다** | 줄글로 뭉쳐 있는 것을 **표·번호 목록·도표**로 바꾼다. 이게 가독성을 가장 크게 올린다 |
| **예시를 보탠다** | 원문 예시가 추상적이거나 업종이 낯설면 **독자에게 익숙한 예시를 새로 만든다** |

**하지 말 것** — 원문에 없는 주장을 만들어 넣는 것. 쉽게 푸는 것과 내용을 바꾸는 것은 다르다.
저자의 결론을 바꾸지 않는다. 보태는 것은 **예시와 구조**뿐이다.

**주의** — 한국어 책은 원문이 이미 한국어라 "빠뜨려도 티가 안 난다."
`digest`에서 대조 패스는 `translate`보다 **더** 중요하다.

## 도표 재작도 — 인라인 SVG

원본 이미지를 그대로 넣지 않고 **다시 그린다.** 이유는 셋이다.
벡터라 인쇄가 깨지지 않고, PDF에서 **글자 검색**이 되고, 라벨을 한글로 바꿀 수 있다.

```html
<figure>
<div class="figbox">
<svg viewBox="0 0 690 230" width="100%">
  <rect x="14" y="24" width="206" height="184" fill="#1f2937" rx="8"/>
  <text x="117" y="54" font-size="14" font-weight="800" fill="#fff"
        text-anchor="middle">WHAT</text>
</svg>
</div>
<figcaption>원문 p158~163을 한국어로 재작도.</figcaption>
</figure>
```

### 기본형 — 3-box 도표 (690×150)

가장 많이 쓰는 형식. 헤더 바(y=8 h=18) · 상자 셋(x=8/236/464 · y=34 · w=216 · h=80) · 상자마다 제목 5.4pt(y=46) + 본문 4.3pt 네 줄(y=58/69/80/91) + 결론 4.5pt(y=106) · 바닥 바(y=120 h=22). `templates/chapter.html` 에 그대로 있다.
**4.3pt 한 줄은 55자 이내**, 표형 도표의 셀은 110자 이내, `<text>` 마다 `font-size` 를 명시한다(`<g>` 상속은 `linegap` 오탐). 표는 셀마다 `<text>` 하나(연속 공백이 접힌다).

주식 · 차트 도서의 **실제 차트는 재작도하지 않는다** — `figure.chart` + 원본 크롭 + `svg.anno` 오버레이. `references/chart-mode.md`.

### 작도 규칙

- `viewBox` 너비는 **690**으로 통일한다 (A4 본문 폭에 맞다)
- 색은 **무채색 계열**만 쓴다: `#1f2937` → `#374151` → `#4b5563` → `#6b7280` → `#9ca3af` → `#b8b8b8` → `#e8e8e8`.
  단계를 나타낼 때 진하기로 순서를 표현한다
- 강조 색은 초록 `#2f6b4a` / 배경 `#eef7f0` 하나만 쓴다
- 어두운 배경 위 글자는 `fill="#fff"`, 보조 텍스트는 `#bbb`~`#ddd`
- **`<text>` 안에 HTML 태그를 넣지 마라.** `</p>`가 섞여 들어가 깨진 적이 있다.
  부분 강조는 `<tspan font-weight="800">`을 쓴다
- 채움 도형이 글자를 가리면 **테두리 호(arc stroke)** 로 바꾼다

### 캡션

원문 페이지를 반드시 밝힌다: `<span class="src">원본 1권 236쪽 재작도</span>` (크롭은 `원본 1권 236쪽`).
독자가 원서와 대조할 수 있어야 하고, `imgcite` 검사기의 정규식 `원본\s*\d+\s*권\s*\d+\s*쪽` 에 걸려야 한다. 여러 쪽은 `4쪽 · 5쪽`(`4~5쪽` 은 통과 못 한다).

## 만화

저자의 일화·실패담을 4컷 SVG로 그린다. 사용자가 특히 만족한 요소다.

**왜 만화인가 — 지면을 쓸 값어치가 있다는 근거.**
Paivio의 이중부호화(글은 언어 경로 1개, 그림은 시각+언어 2개 경로로 저장),
Standing(1970)의 재인 실험(2,000여 장을 며칠 뒤에도 90% 이상 알아봄),
Mayer의 멀티미디어 학습 원리(글만 볼 때보다 글+그림이 낫다).
**사전지식이 적을수록 효과가 크다** — 처음 보는 분야일수록 만화를 먼저 준다.
지면이 모자랄 때 *"만화를 빼고 도표를 늘릴까"* 하는 유혹이 오면 이 절을 다시 읽어라.
둘은 대체재가 아니다. 도표는 구조를, 만화는 **서사와 맥락**을 나른다.

- 대상 — 저자의 무너짐/전환점 같은 **서사가 있는 대목**. 개념 설명에는 만화보다 도표가 낫다
- 형식 — 4컷 가로 배치, 막대 인간(stick figure), 말풍선은 한국어
- **말풍선이 인물과 겹치지 않게** 배치한다. 겹침은 렌더해서 눈으로 확인한다

## 예시 (`translate`는 한국 사례 / `digest`는 쉬운 예시)

`translate` — 원문 사례가 미국 맥락(체육관 프랜차이즈, 달러 금액)이면 한국 독자용으로 새로 만든다.
`digest` — 원문 예시가 추상적이거나 업종이 낯설면 **독자에게 익숙한 예시를 보탠다.**
이때 원문 예시를 **지우지 말고** 그 옆에 나란히 둔다. 원문 대조가 가능해야 한다.

```html
<div class="kr-case">
<span class="tag">사례 A</span>
<h4>추천 성장 방정식을 자기 숫자로 — 필라테스 스튜디오</h4>
<pre>월초 회원 100명
이번 달 이탈 8명   → 이탈률 8%</pre>
</div>
```

- **한 인물(K)을 두고 그 사람의 숫자로 따라간다.** 권마다 예시 3개 — 하나는 숫자 계산, 하나는 의사결정, 하나는 원문 규칙을 독자의 서식으로 바꾼 것(함정 #89)
- `<pre>` 표는 **한 줄 100단위(한글 2 · ASCII 1) 이내 · 4열 이내 · 판정 열 ≤ 18~22자**. 손으로 정렬하지 말고 `east_asian_width` 패딩으로 생성한다(`prewidth.py 100` 이 검사한다)
- **숫자를 넣는다.** 원문 프레임워크에 실제 값을 대입해 계산 과정을 보여준다
- 업종은 한국에서 흔한 것으로: 필라테스, 학원, 배달, 미용실, 카페, 병원
- 원문 개념과 **어디가 같고 어디가 다른지** 밝힌다

## 덮고 쓰기 — 회상 지면 (챕터마다 필수, 시험지 앞)

시험지는 대부분 **객관식**이라 보기를 보고 고르는 재인(recognition) 훈련이다.
실력은 **보기 없이 백지에서 꺼낼 때** 확인된다. 그 자리를 이 한 쪽이 맡는다.

핵심은 **뼈대와 개수만 인쇄하고 내용을 비우는 것**이다.
개수를 인쇄하는 이유는 그것이 가장 강한 인출 단서이기 때문이다 —
"핵심이 3개였다"를 알면 두 개를 떠올린 뒤 **하나가 비었다는 사실**을 스스로 안다.
개수를 지우면 몇 개를 잊었는지도 모른 채 넘어간다.

```html
<div class="recall">
<h3>덮고 쓰기 — 3장</h3>
<div class="how">여기서 책을 덮으세요. 앞으로 돌아가지 말고, 떠오르는 대로 채웁니다.
  빈칸이 남아도 괜찮습니다 — 어디가 비었는지 아는 것이 이 쪽의 목적입니다.</div>

<p>이 장의 뼈대는 <span class="cnt">7</span>단계다.</p>
<ol>
  <li><div class="hint">힌트 — 무엇을 파느냐가 아니라 <b>누구에게</b></div><div class="line"></div></li>
  <li><div class="line"></div></li>
</ol>

<div class="after">다 쓴 뒤 본문으로 돌아가 맞춰보고, <b>빈칸이었던 항목에만</b> 표시해 두세요.
  다음 복습일에 그 항목부터 봅니다.</div>
</div>
```

현행 마크업은 더 단순하다 — 항목마다 `<p>N. 힌트 (도표 N)</p><div class="line"></div>` 한 쌍, 12항목, 각 **한 줄 ≤ 45자**(두 줄로 감기면 마지막 `.line` 이 다음 쪽으로 넘어간다, 함정 #102). `templates/chapter.html` 참조.

**규칙**

- **장 끝, 시험지 바로 앞**에 놓는다. 덮고 쓰기 → 시험 → 채점 → 튜터 순서다
- `.recall` 은 `page-break-before: always` 라 항상 새 쪽에서 시작한다. **한 장에 한 쪽**을 넘기지 마라
- 뼈대 항목은 **5~8개**. 그 장의 절 제목이나 프레임워크 단계를 그대로 쓴다. 새로 만들지 않는다
- **힌트는 절반 이하 항목에만** 단다. 전부 달면 그냥 읽기가 된다
- **힌트는 빈 줄보다 앞에 온다.** `.recall .hint` 는 `margin-bottom` 만 갖는 설계다.
  줄을 먼저 두면 렌더에서 **힌트가 밑줄 아래로 떨어져** 다 쓴 뒤에야 눈에 들어온다
- 항목 이름을 인쇄하지 마라. **번호와 빈 줄만** 준다. 이름을 주면 재인으로 돌아간다
- `.after` 의 "빈칸이었던 항목에 표시"는 **계획표의 복습 칸과 연결된다.** 표시가 다음 복습의 목록이다

## 시험문제 + 정답 (챕터마다 필수)

챕터 끝에 **시험지 → 정답지** 순으로 붙인다. 두 블록을 분리하는 것이 핵심이다.
정답이 문제 바로 아래 있으면 눈에 들어와서 시험이 되지 않는다.

### 구성

챕터당 **9~13문항**. 유형을 섞는다.

| 유형 | 비중 | 목적 |
|---|---|---|
| **객관식** (4지선다) | 절반 정도 | 개념·정의를 정확히 아는지 |
| **단답** | 3~4문항 | 프레임워크 이름, 숫자, 순서를 기억하는지 |
| **서술 · 적용** | 1~2문항 | **적용**할 수 있는지. "당신의 사업에 대입하면" 형태 |
| **서술 · 설명** | **1문항 (필수)** | **인출**할 수 있는지. "처음 듣는 사람에게 3문장으로" 형태 |

**설명형은 적용형을 대체하지 않는다. 둘은 다른 능력이다.**
적용형은 *가진 지식을 자기 상황으로 옮기는* 것이고, 설명형은 *보기 없이 백지에서 꺼내는* 것이다.
객관식이 절반이라 시험지 전체가 **재인(recognition)** 쪽으로 기울어 있었다. 그 자리를 메운다.

```html
<div class="q"><span class="qtype">설명</span>Q9. 포인터를 <b>처음 듣는 사람에게
3문장으로</b> 설명하시오. 전문용어를 쓰지 말 것.</div>
<div class="blank"></div><div class="blank"></div>
```

**답안줄은 2줄로 제한한다.** 적용형의 3줄을 그대로 쓰면 시험지가 길어져
빈 페이지 함정(아래 "쪽 나눔")을 건드린다. 3문장짜리라 2줄이면 충분하다.

- 난이도는 **쉬움 → 어려움 순**으로 배치한다
- 마지막 1~2문항은 `.qtype hard` 로 표시하고, **여러 개념을 엮어야 풀리게** 만든다
- 답이 본문에 **그대로 적혀 있지 않은** 문항을 최소 2개 넣는다. 읽고 이해했는지 확인하는 자리다

### HTML 형식

**현행 표준 — 문항마다 `div.qa` 하나로 감싼다.** 문항과 답안줄이 갈라져 빈 쪽이 생기는 것을 막는다(함정 #65 · #66). 한 `qa` 에 여러 문항을 몰면 페이지 분할이 안 된다.

```html
<div class="exam">
<h3>시험문제 &mdash; 2권</h3>
<div class="info">32문항 · 객관식 · 단답 · 서술 혼합 · 합격선 23개</div>
<div class="qa"><div class="q"><span class="qtype">객관식</span>Q1. …? (31)</div>
<div class="opts"><div>① …</div><div>② …</div><div>③ …</div><div>④ …</div></div></div>
<div class="qa"><div class="q"><span class="qtype">단답</span>Q2. …? (32)</div><div class="line"></div></div>
<div class="qa"><div class="q"><span class="qtype hard">설명</span>Q32. … 3문장으로.</div><div class="line"></div><div class="line"></div></div>
</div>
```

문항 끝의 `(31)` 은 책 쪽이다. 권당 **30~36문항**(총정리는 40). 아래는 초기 형식(`.blank`)으로, `class="q"` 만 세므로 둘 다 `stats` 를 통과하지만 **새 책은 위 형식**으로 쓴다.

```html
<div class="exam">
<h3>시험문제</h3>
<div class="info">8문항 · 정답은 다음 쪽 · 먼저 풀고 틀린 항목의 본문으로 돌아갈 것</div>

<div class="q"><span class="qtype">객관식</span>Q1. 리드 마그넷의 목적은?</div>
<div class="opts">
  <div>① 즉시 매출을 올린다</div>
  <div>② 문제 하나를 진짜로 풀어주고 다음 문제를 드러낸다</div>
  <div>③ 광고비를 줄인다</div>
  <div>④ 경쟁사를 차단한다</div>
</div>

<div class="q"><span class="qtype">단답</span>Q5. 핵심 4가지를 모두 쓰시오.</div>
<div class="blank"></div>

<div class="grp"><b>적용 문제</b></div>
<div class="q"><span class="qtype hard">서술</span>Q8. 본인 사업의 LTGP:CAC를 계산하고,
3:1에 못 미친다면 무엇부터 손볼지 근거와 함께 쓰시오.</div>
<div class="blank"></div><div class="blank"></div><div class="blank"></div>
</div>

<div class="answers">
<h3>정답 및 해설</h3>
<div class="a"><b>Q1 → ②</b> 리드 마그넷은 매출이 아니라 <b>참여 리드</b>를 얻는 도구다.
  <div class="why"><b>왜 ①이 아닌가</b> — 즉시 매출이 목적이면 그건 핵심 오퍼지 리드 마그넷이 아니다.</div>
</div>
</div>
```

### 해설 규칙

- **정답만 쓰지 마라.** 왜 그 답인지 한 줄로 근거를 준다
- 헷갈리기 쉬운 오답 하나는 **왜 아닌지**를 `.why` 로 밝힌다. 이게 학습 효과의 대부분이다
- 서술형은 **모범답안의 뼈대**(포함해야 할 요소 3~4개)를 제시한다. 정답 하나로 못 박지 않는다
- 본문 어디를 다시 볼지 알려준다: `→ 본문 "가치 방정식" 절 참조`

### 합격선 (정답지 맨 끝, 챕터마다 필수)

해설은 *"왜 이 답인가"* 를 말해주지만 **"넘어가도 되는가"** 는 말해주지 않는다.
그래서 대부분 다 맞았든 절반을 틀렸든 그냥 다음 장으로 간다.
**읽고 이해된 느낌과 실제 실력은 자주 반대 방향이다.** 숫자 기준 한 줄이 그걸 가른다.

```html
<div class="cut">
<b>몇 개 맞았나요?</b>
<div>· <b>10개 이상</b> — 다음 장으로.</div>
<div>· <b>7~9개</b> — 틀린 문항의 <b>그 절만</b> 다시 읽고 넘어갑니다.</div>
<div>· <b>6개 이하</b> — 이 장을 다시 읽습니다. 덮고 쓰기부터 다시.</div>
<div class="warn2">다 아는 것 같았는데 6개 이하였다면,
  그건 실력이 아니라 <b>읽은 느낌</b>이었던 겁니다. 이 신호가 이 쪽에서 가장 중요합니다.</div>
</div>
```

- 기준은 **문항 수의 약 80% / 60%** 로 잡는다. 12문항이면 10 / 7~9 / 6 이하
- **세 줄 다 행동을 지정한다.** "복습하세요"는 행동이 아니다. *"틀린 문항의 그 절만"* 이 행동이다
- 마지막 경고 줄(`.warn2`)은 **그대로 둔다.** 자기 판단을 의심하게 만드는 것이 이 블록의 목적이다
- 현행 표준은 `.warn2` 에 **급소 3문항**을 지정한다 — `<b>급소 3문항</b> — Q8 · Q13 · Q23. 셋 중 둘 이상 틀리면 통과해도 이 권을 다시 읽는다.` 정의 문항을 사례 문항보다 앞에 둔다

### 안내 문구

`_front.html`에 이렇게 적는다 —
**"각 챕터의 시험문제를 먼저 풀고, 틀린 항목의 본문으로 돌아가는 방식이 가장 효율적이다."**

### 쪽 나눔

`.exam` 은 `page-break-inside: auto` 라서 길면 자연스럽게 넘어간다.
`.exam .q` 에 `page-break-after: avoid` 가 걸려 있어 **문항과 선택지가 갈라지지 않는다.**
정답지 `.answers` 는 `page-break-before: always` 라 **반드시 다음 쪽**에서 시작한다.

**주의 — 마지막 문항의 `.blank` 개수를 확인하라.**
답안줄이 페이지 끝을 아슬아슬하게 넘으면 **박스 아래 테두리와 줄 하나만 다음 장에 남아
사실상 빈 페이지가 생긴다.** Chrome은 `.blank` 의 `page-break-before: avoid` 를 무시하므로
CSS로 못 막는다.

빌드 후 `_verify.txt` 에 **빈 페이지 번호**가 뜨면 이 경우를 먼저 의심하고,
**마지막 문항의 답안줄을 1~2개 줄여라.** 서술형이라고 3줄을 기계적으로 넣지 말 것.

## 종합시험 (책 끝에 한 번, `ch99.html`)

장별 시험은 **그 장 안에서만** 묻는다. 그래서 장을 넘나드는 질문에 약해진다.
마지막에 **장을 섞은 12문항**을 한 쪽 붙인다.

**단, 섞는 것은 끝에서만 한다.** 처음부터 섞으면 안 된다 —
비슷해서 헷갈리는 재료일수록 섞기가 효과적이지만,
**기초가 없는 상태에서 섞으면 오히려 나빠진다.** 그래서 순서는
*장별 시험(묶어서) → 종합시험(섞어서)* 이고, 이 순서를 바꾸지 않는다.

**규칙**

- **12문항 · 서로 다른 장에서 뽑되, 장별 시험 문항을 그대로 옮기지 않는다.**
  같은 문항을 다시 내면 그 문항을 외웠는지만 확인된다
- **절반 이상은 두 장 이상을 엮어야 풀린다.** 이게 종합시험의 존재 이유다
  (예: *"3장의 헤드라인 공식을 8장의 구조화 단계 중 어디에 넣어야 하는가"*)
- 각 문항 끝에 **출처 장을 표시**한다: `(3장·8장)`. 틀렸을 때 어디로 돌아갈지 알아야 한다
- 합격선을 똑같이 붙인다. 여기서 6개 이하면 **책을 덮고 계획표의 복습일부터 다시** 돈다
- `book.json` 의 `titles` 에 `"ch99": "총정리 — … · 종합시험"` 을 넣어 목차와 북마크에 뜨게 한다
- 현행 표준의 `ch99` 는 **총정리 권**이다 — 책의 지도(도표) · 용어집 40 · 숫자 24 · 체크리스트 · 종합시험 40문항, 그리고 **만화 2편 · 예시 3개**도 넣는다(`stats` 가 요구한다, 함정 #53). 덮고 쓰기는 없다(`blocks` 예외). 앞 권을 베끼지 말고 원문 대조를 한 번 더 한다(함정 #78). 인터뷰 · 에세이 책은 각 권 도표의 고정 형식에서 `re` 로 뽑아 조립한다

## 튜터 프롬프트 (챕터마다 필수, 정답지 뒤)

**PDF는 정적이라 대화형 점검을 넣을 수 없다. 그런데 프롬프트는 인쇄할 수 있다.**
독자가 복사해 아무 AI에게 붙여넣으면 그 챕터 전용 튜터가 켜진다. 책이 없어도 된다.

`build.py blocks`가 **챕터마다 `.tutor`가 있는지 검사**하고, 없으면 종료 코드 1을 낸다.

```html
<div class="tutor">
<h4>이 장을 제대로 이해했는지 확인하려면</h4>
<div class="how">아래를 복사해 아무 AI에게 붙여넣으세요. 책이 없어도 됩니다.</div>
<pre>『프로그램은 어떻게 작동하는가』 제4장의 '스택과 큐, 포인터' 개념에 대해
내 튜터가 되어줘.

규칙:
- 한 번에 하나의 질문만 해
- 나에게 강의하지 마
- 내 이해의 빈틈을 찾아
- 내 답이 얕으면 더 깊게 파고들어

시작해.</pre>
</div>
```

**규칙**

- **그 챕터 전용으로 채워 넣는다.** 책 제목·장 번호·**그 장의 핵심 개념 2~3개**를
  프롬프트 안에 미리 박아둔다. 독자가 채워 넣게 만들면 아무도 안 쓴다
- 규칙 네 줄(하나씩·강의 금지·빈틈·심화)은 **그대로 둔다.** 이게 튜터와 챗봇을 가른다
- 블록은 **정답지 뒤**에 놓는다. 시험을 먼저 풀고 → 채점하고 → 그다음이 심문 순서다
- 길게 쓰지 마라. 프롬프트가 길면 복사하기 싫어진다

## 학습 계획표 (`_front.html`, 목차 다음)

목차는 **무엇이 들어 있는지**만 알려준다. 계획표는 **언제 무엇을 끝낼지**를 준다.
82쪽짜리 문서를 그냥 던지면 어디서 끊어야 할지 알 수 없다.

**그리고 계획표는 앞으로만 가면 안 된다.**
1일차부터 6일차까지 새 내용만 쌓는 계획은, 6일차에 1일차 내용이 남아 있지 않다.
같은 총량이라도 **며칠에 나눠 다시 꺼낼 때** 훨씬 오래 간다.
그래서 계획표에는 **"오늘 꺼낼 것"** 열이 반드시 있다.

```html
<div class="plan">
<h3>학습 계획 — 5일</h3>
<table>
<tr><th>일차</th><th>새로 배울 것</th><th>쪽</th>
    <th>오늘 꺼낼 것</th><th>그날의 산출물</th></tr>
<tr><td>1일차</td><td>제1~2장</td><td class="c">28쪽</td>
    <td class="rev">—</td>
    <td class="out">2진수 ↔ 10진수 변환 5문제를 손으로 풀기</td></tr>
<tr><td>2일차</td><td>제3~4장</td><td class="c">25쪽</td>
    <td class="rev"><b>1장·2장</b> 덮고 쓰기 다시</td>
    <td class="out">스택과 큐를 그림 안 보고 그려보기</td></tr>
<tr><td>5일차</td><td>제7~8장</td><td class="c">26쪽</td>
    <td class="rev"><b>4일 전(1장)</b> · <b>1일 전(5~6장)</b> 시험 틀린 문항만</td>
    <td class="out">…</td></tr>
<tr class="spare"><td>7일차</td><td colspan="2">예비일 — 밀린 것 보충</td>
    <td class="rev">여기까지 표시해 둔 빈칸 전부</td>
    <td>새 진도 없음</td></tr>
</table>
</div>
```

**규칙**

- **"산출물" 칸이 이 표의 전부다.** "읽었다"가 아니라 **"증명했다"** 로 넘어가는 조건이다.
  *"1~2장 읽기"* 는 산출물이 아니다. *"변환 5문제 손으로 풀기"* 가 산출물이다
- 산출물은 **그 범위의 시험문제나 설명형 문항에서 뽑는다.** 새로 만들지 마라
- 일수는 **하루 25~30쪽**을 기준으로 나눈다. 챕터 경계를 자르지 않는다
- 표는 행 단위로만 쪽나눔을 막는다 (`.plan tr`). 표 전체에 걸면 빈 페이지가 생긴다 — 함정 #8

**"오늘 꺼낼 것" 칸 규칙 (1-4-7-14)**

- 간격은 **1일 · 4일 · 7일 · 14일 전**을 기준으로 잡는다. 계획이 6일이면 1·4일 전까지만 들어간다
- 꺼내는 대상은 **덮고 쓰기에서 빈칸이었던 항목 + 시험에서 틀린 문항**이다.
  *"3장 복습"* 이라고 쓰지 마라. 그건 다시 읽기고, 다시 읽기는 가장 효과가 낮은 방법이다
- 1일차의 칸은 `—` 로 둔다. 억지로 채우지 않는다
- **마지막 날 다음에 예비일 1일**을 둔다 (`.plan .spare`).
  하루만 밀려도 계획 전체가 무너지는 것을 막는 자리다. 새 진도는 넣지 않는다
- 예비일 다음에 **종합시험**을 배치한다
