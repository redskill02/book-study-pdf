# 원문 대조 패스

집필이 끝난 뒤 **집필과 분리된 별도 패스**로 돌린다.
컨택트시트까지 돌리고도 `$100M Leads`에서 **누락 9건**이 나왔다. 이 패스는 생략할 수 없다.

## 왜 누락이 생기나

이미지는 확인했는데도 **본문 텍스트의 h4 하위 절이 통째로 압축**되면서 소제목만 남고 내용이 날아간다.
특히 **"6가지 방법" 같은 목록형 구조**는 표 한 장으로 요약하고 넘어가기 쉽다.
하지만 원문은 각 항목마다 사례·수치·프로세스를 갖고 있다.

`$100M Leads`에서는 "가치를 더 주는 6가지"가 **표만 있고 본문이 완전히 비어 있었다.**
그 안에는 Gym Launch가 첫 7일에 광고+판매를 시켜 LTGP를 3배로 만든 사례가 들어 있었다.

## 절차

### 1. 헤딩 전수 대조

```bash
python "$SKILL/scripts/audit.py" \
  "<원문 md 폴더>" "<학습노트 html 폴더>"
cat _audit.txt
```

`??` 로 표시된 헤딩은 학습노트에서 못 찾은 것이다. **원문을 열어 실제로 확인한다.**
자동 매칭은 힌트일 뿐이라 오탐이 있다.

### 2. 열거형 표현 세기

`_audit.txt` 아래쪽에 `N가지` / `N ways` / `N steps` 목록이 나온다.
**N개 항목이 각각 본문을 갖고 있는지 센다.** 표만 있고 내용이 없으면 누락이다.

### 3. 키워드는 반드시 원문에서 뽑는다

사전 계획서 기준으로 키워드를 뽑으면 **원문에 없는 개념**을 찾느라 시간을 버린다.
실제로 파랑새·다이아몬드 우화, 중립/안티 콜아웃, PS문을 찾다가 시간을 썼는데
**전부 그 책에 없는 내용**이었다.

```bash
# 학습노트에 있는지 확인
cd <html폴더> && for k in 키워드1 키워드2; do
  printf "%-14s " "$k"; grep -l "$k" ch0*.html | tr '\n' ' '; echo
done
```

### 4. 이미지 커버리지

컨택트시트 계획표의 재작도 대상 수와 **실제로 그린 SVG 수**를 센다.

```bash
grep -c "<svg" ch0*.html
```

Leads에서는 계획 61개 대비 실제 47개였고, 그 차이가 누락과 겹쳤다.

## 심각도 분류

발견한 누락은 **심각도 순으로** 채운다. 이 순서를 사용자가 명시적으로 요구했다.

| 등급 | 기준 | 예시 |
|---|---|---|
| 🔴 **높음** | 책의 **뼈대인 프레임워크**. 이게 빠지면 그 장이 성립하지 않는다 | WHAT·WHO·WHEN, 속삭임→놀림→외침 |
| 🟡 **중간** | **실행 프로세스·의사결정 도구**. 없어도 읽히지만 못 써먹는다 | 타겟팅 절차, 사고실험 |
| 🟢 **낮음** | **사례·팁·마무리 서사**. 이해를 돕지만 대체 가능하다 | 개인적 교훈, 우화 |

## 보완 후 절차

1. 삽입 위치를 정하고 채운다
2. **`grep -n "<h2\|<h3"`로 헤딩 순서를 확인한다** — 다음 대단원으로 넘어간 적이 있다
3. `python build.py all && python build.py merge`
4. 새로 그린 SVG 페이지를 렌더해서 **눈으로 본다**
   ```bash
   python build.py find "핵심키워드"
   python build.py page 47
   ```
   → Read 도구로 PNG 확인
5. `python build.py deploy`
6. 진도표에 **보완 이력 표**를 남긴다 (무엇이 왜 빠졌는지, 어디에 넣었는지)

## 최종 검증 체크리스트

- [ ] `build.py stats` — 종료 코드 0 (표지 수치 = 실제 개수)
- [ ] `build.py blocks` — 종료 코드 0 (챕터마다 시험지·정답지·튜터 프롬프트)
- [ ] `build.py headings` — 종료 코드 0 (절 번호 연속)
- [ ] `build.py render` — 만화 100% + 상위 10장 이상 눈으로 확인
- [ ] 빈 페이지 0
- [ ] 한글 폰트 임베딩 OK (Malgun)
- [ ] 북마크 = 챕터 수 + 1(표지)
- [ ] 배포 폴더에 **중복 파일명 없음** (`ch01.pdf` 같은 임시명이 남지 않았는지)
- [ ] 진도표·체크리스트 갱신

## `digest` 모드 — 방법이 다르다

한국어 책은 원문이 이미 한국어라 **빠뜨려도 티가 안 난다.**
`translate`는 번역이 안 된 부분이 눈에 띄지만, `digest`는 "요약했으니 됐다"고 넘어가기 쉽다.

### ⚠️ 제목 문자열로 대조하면 안 된다

예전에 이 문서는 *"digest는 자동 매칭이 실제로 유효하니 `??` 표시를 신뢰해도 된다"* 고 적고 있었다.
**틀렸다.** 『프로그램은 어떻게 작동하는가』에서 제목 문자열로 대조했더니
**18건이 뜨고 18건 전부 오탐**이었다.

이유는 명확하다 — **digest는 제목을 의역하는 것이 목적**이기 때문이다.

| 원문 소제목 | 노트의 제목 |
|---|---|
| 함수 호출의 구조 | 함수 호출 — 점프만으로는 안 되는 이유 |
| 컴퓨터가 계산을 틀리는 이유 | 왜 틀리는가 — 표현할 수 있는 값이 띄엄띄엄하다 |
| 메모리에 읽어와야 실행됨 | 대전제 — 메모리에 올려야 실행된다 |

위험한 것은 오탐 자체가 아니다. **오탐이 18건씩 쌓이면 진짜 누락 1건이 그 속에 묻힌다.**

### 그래서 `audit.py`가 하는 일

`--mode digest`(또는 `book.json`의 `mode`)면 제목이 아니라 **내용어(명사) 단위**로 대조한다.

- 제목에서 기능어를 걷어내고 **내용어**만 뽑는다
- 조사 절단(`반복처리의` → `반복처리`)과 **띄어쓰기 복원**(`2진수와16진수` → `2진수`)까지 시도한다
  — 원문 OCR은 띄어쓰기를 자주 먹는다
- 장 표시(`제1장`, OCR로 뭉개진 `제1정`·`제8광`)와 코드 조각 헤딩은 **아예 제외**한다
- 판정을 세 갈래로 나눈다

| 결과 | 뜻 | 할 일 |
|---|---|---|
| **내용어 0개** | 진짜 누락 후보 | **반드시 원문을 열어 확인** |
| 내용어 1개만 | 약하게 다뤘을 수 있음 | 훑어본다 |
| 나머지 | 다뤄진 것으로 본다 | — |

실측 — 원문 헤딩 204개에서 **후보 5건**만 남았고, 그중 4건은 원문 OCR 오류(`알러두기`, `설병할까요`),
1건만 실제로 열어볼 가치가 있었다. **204 → 5 → 1**이면 쓸 만한 신호 대 잡음비다.

### 그 외에 digest에서 봐야 할 것

- [C] 앵커 대조는 **더 잘 먹힌다.** 한국어끼리라 고유명사·용어가 그대로 남는다
- **"쉽게 쓴다면서 내용을 잘라낸 것"** 을 본다.
  원문의 단서 조항·예외·반대 사례가 사라지지 않았는지 확인한다
- **원서 자체의 OCR 오류**를 노트로 옮기지 않았는지 본다.
  『프로그램은 어떻게 작동하는가』에는 `43비트의 레지스터`가 있었는데
  주소 범위가 `00000000~FFFFFFFF`니 **32비트**가 맞다.
  **문맥으로 검산되는 수치(비트 수·진법 변환·바이트 수)는 반드시 검산한다.**
