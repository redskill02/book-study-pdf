# 주식 · 차트 도서 — 원본 크롭 + 한글 주석 모드 (`figures: chart`)

주식 · 차트가 실린 책은 **원본 도판을 재작도하면 안 되는 경우**가 있다.
『나는 주식투자로 250만불을 벌었다』 · 『주식 매매하는 법』 · 『대형주 추세추종 투자법칙』에서 확립하고, 이후 30권 넘게 검증했다.

**왜** — 도판에 저자가 사고판 자리(Ⓐ~Ⓖ · A·B·C)가 인쇄되어 있고 본문이 그 기호로 서술한다.
다시 그리면 "교과서 속 깔끔한 패턴"이 되어 **실제 차트의 지저분함을 읽는 기술**이라는 학습 목표가 사라진다.

---

## 1. 도판 5분류 ★ 핵심

| 유형 | 정의 | 처리 | 왜 |
|---|---|---|---|
| **A** 개념도 · 표 | 프레임워크, 분류표, 순서도, 매매 체크리스트, 재무표 | **한글 SVG 재작도** | 원본보다 선명하고 검색된다 |
| **B** 패턴 도해 | 이상화된 캔들 · 이평선 도식 (갭, 헤드앤숄더, 정배열) | **한글 SVG 재작도** | 원본이 이미 도식이라 재작도가 더 깨끗하다 |
| **C** 실제 종목 차트 · 기록표 | 특정 종목 · 기간의 진짜 차트, 저자의 매매 일지 | **원본 크롭 + 한글 주석 오버레이** | 실물이 증거이자 훈련 자료다 |
| **D** 사진 · 화면 | 사진, 사이트 캡처 | **원본 크롭** + UI 노후 각주 | 절차 설명이라 실물이 필요 |
| **D′** HTS · MTS 설정 화면 · 수식이 적힌 화면 | 534×847 · 40~80KB 캡처 | **A 로 승격 — 재작도**(한글 화면 목업) | 크롭하면 글자가 안 읽힌다. `highest(h,period)*0.98` 같은 수식은 캡처에서 안 읽힌다 |
| **E** 장식 | 아이콘, 부속표지, 인물사진, 빈 말풍선, 장 도비라 색지 | **버린다** | |

**판정 기준** — C 의 기준은 "차트처럼 생겼는가"가 아니라 **"저자의 매매 흔적이 인쇄되어 있는가"** 다.
- 캔들을 끄고 이평선만 남긴 손 주석 도해 → 개념도 → **A**.
- 한국어판이 차트 라벨을 이미 한글로 다시 인쇄한 책 → 재작도할 이유가 없다 → 크롭만 하고 설명을 붙인다. 재작도는 개념도에만.
- **같은 차트가 두 번 실리면 둘 다 넣는다.** 앞은 상승 화살표만, 뒤는 하락 · 횡보까지 — 나란히 놓는 것 자체가 논증이다.
- **색이 정보인 도판**(검정=상승추세 · 빨강=하락추세 · 연필=정상 · 파랑=사후수정)은 **원본 크롭 + 원본에 없는 '읽는 열쇠' 도해**가 한 세트다. 빈 서식 도해를 새로 그려 앞에 붙여야 표가 읽힌다.

## 2. 파이프라인 — 이중 트랙

원본은 600dpi · 수백 MB~1.3GB 다. MinerU 에 그대로 넣으면 느리고 죽는다. 그런데 크롭은 원본 해상도가 있어야 쓸 만하다.

```
원본 PDF (_src/srcN.pdf, 600dpi)
├── 트랙 1 · 구조화 ── downsample.py ─→ _src300/srcN.pdf (300dpi · 쪽 크기 pt 보존)
│                      tojpg.py ─→ _mineru_in/srcN.pdf (JPEG q80 · 5~10배 작다)  ─→ MinerU ─→ out N/ (텍스트 · bbox)
└── 트랙 2 · 도판   ── crop.py ─→ 그 bbox 로 원본에서 직접 크롭 ─→ crops/vN_pPPP_a.jpg + crops/_index.txt
```

```bash
python downsample.py                       # _src/*.pdf -> _src300/  (_downsample.txt)
python tojpg.py _src300/src1_정방향.pdf _mineru_in/src1.pdf   # 747MB 무압축 사본이 MinerU 를 죽였다 — JPEG 로
python run_mineru.py 1                     # 또는 _pipeline.py (rotate 포함)
python crop.py                             # out*/**/middle.json 의 bbox -> crops/  (기본 400dpi · 가로 상한 1600px · JPEG q88)
python _cs.py 1 400 _cs1.png 4 v1          # 크롭 컨택트시트 (쪽 1~400 · 4열 · 1권)
python view.py v1_p017_a 1200              # 크롭 하나 확대 -> pdf/_v_v1_p017_a.png
python idsheet.py _id03.png v1_p068_a v1_p069_a v1_p070_a     # 캡션 쓰기 전 ID 확정
```

`downsample.py` 가 쪽 크기(pt)를 보존하므로 MinerU 의 bbox 좌표가 원본과 1:1 로 맞는다(8장 전부 정렬 오차 0).
가로 쪽이 `_정방향.pdf` 에 안 잡히면 PIL 로 `_r.jpg` 회전본을 따로 만든다.

### 함정 다섯 (전부 실제로 겪음)

1. **크롭 타입은 `image` · `table` · `chart` 셋 다 넣는다.** MinerU 는 주가 차트를 `chart` 로 분류한다. 다바스는 차트가 `chart`, 리버모어는 전면 기록표가 `table` 이었다(54장 중 table 21 / image 22 / chart 11). 하나만 빠져도 알맹이를 통째로 잃는다. `crop.py` 는 셋을 다 본다.
2. **전면이 도판인 쪽은 bbox 를 믿지 말고 전면 크롭한다.** bbox 가 아래 캡션을 자르는데, 그 캡션이 "규칙 설명 6-c 참조"처럼 **도판과 본문을 잇는 유일한 고리**일 수 있다.
3. **오버레이 `viewBox` 는 `crops/_index.txt` 실측값을 쓴다.** 눈대중 2320 vs 실제 2334 → 0.6% 오차라 눈에 안 띄지만 마커가 조금씩 밀린다.
4. **주석 범례가 데이터를 가린다.** 폭을 차트 빈 사분면에 맞추고 **반드시 렌더해 눈으로 확인**한다(790 → 670 으로 줄여 1958년 봉을 살렸다).
5. **크롭 파일명(p312_a)만 보고 그림 번호 · 종목명을 붙이면 한 칸씩 밀린다.** `_crops_by_bookpage` 나 요약만 믿지 말고 `idsheet.py` 로 후보를 세로로 이어 붙여 **티커를 눈으로 읽는다.** 캡션에 종목명을 쓰는 순간부터 필수다.

### 작은 크롭

- `imgres` 검사기 기준 **가로 900px 미만은 지면에 못 싣는다.** 게이트에서 미리 목록을 적어 재작도(A) 대상으로 고정하거나, bbox 로 560dpi 재크롭한다.
- 작은 크롭이 많은 장(모델 종목 50선)은 **PIL 몽타주 6~8장 + 한글 라벨(malgun)** 로 묶어 한 도표로 만든다(`figure.chart.half` 는 가로형 두 장).

## 3. 지면에 넣는 방법 — 주석 오버레이

```html
<figure class="chart">
<div class="wrap">
<img src="crops/v2_p109_b.jpg" alt="삼성증권 일봉에 상승·하락 추세 구간이 점선으로 나뉘고 한글 화살표 주석이 붙은 차트">
<svg class="anno" viewBox="0 0 1598 1273" preserveAspectRatio="none">
<defs><marker id="ah" markerWidth="11" markerHeight="11" refX="9" refY="5" orient="auto"><path d="M0,0 L10,5 L0,10 z" fill="#b91c1c"/></marker></defs>
<rect class="lbbg" x="900" y="760" width="660" height="250" rx="12"/>
<rect class="bx"   x="900" y="760" width="660" height="250" rx="12"/>
<text x="920" y="812" font-size="34" class="lb">들쭉날쭉한 선 = 종가</text>
<text x="920" y="868" font-size="34" class="lb">매끄러운 선 = 20일 평균</text>
<line x1="1300" y1="756" x2="1460" y2="360" class="ar"/>
</svg>
</div>
<figcaption><b>도표 5 &mdash; ①번 규칙을 한 종목에서 네 번 반복해 보여 준다.</b>
<b>삼성증권(016360)</b>의 일봉이다. 주목할 곳은 화살표가 붙은 자리 &mdash; 꼭짓점이 아니라 <b>선을 깬 다음 봉</b>에 '이탈 매도'가 붙어 있다.
<span class="src">원본 2권 109쪽 (책 259쪽)</span></figcaption>
</figure>
```

`assets/style.css` 의 `figure.chart` 블록이 이 구조를 지탱한다. 핵심은 —
- `.wrap { display:inline-block }` — 이미지가 줄어들 때 오버레이 SVG 도 같이 줄어 좌표가 유지된다. `block` 이면 어긋난다.
- `img { max-height:166mm }` — 세로로 긴 차트가 쪽을 통째로 넘기는 것을 막는다. 캡션이 짧으면 `figure.chart.tall`(210mm), 가로형 두 장은 `.half`(100mm).
- `.lb { paint-order:stroke; stroke:#fff; stroke-width:11 }` + `.lbbg`(흰 깔개) — **둘 다 필요하다.** 후광만으로는 격자선 위에서 취소선처럼 보인다.
- 원본 마커 번호를 CSS 로 흰색 덮지 않도록 `.mkt` 는 마커 원 안의 숫자에만 쓴다(함정 #91).

**규칙 세 가지**
1. **마커 · 라벨은 한 크롭에 3~4개까지.** 좌표를 눈으로 잡아야 하므로 개수를 제한한다. 그 이상은 캡션으로.
2. **캡션에 "무엇을 보라"를 반드시 쓴다.** 차트만 넣고 설명이 없으면 스캔을 옮겨 붙인 것에 불과하다. 차트 안 숫자는 **이미지에서 직접 확인한 것만** 적는다(역방향 대조가 못 찾는다, 함정 #83).
3. **출처를 적는다** — `<span class="src">원본 N권 M쪽</span>`. `imgcite` 검사기의 정규식은 `원본\s*\d+\s*권\s*\d+\s*쪽` 이다. 여러 쪽이면 `원본 3권 4쪽 · 5쪽`("4~5쪽"은 통과 못 한다).

**두 방식** — 원본 마커가 촘촘하면 **화살표 + 라벨**, 차트에 빈 사분면이 있으면 **범례 상자**(훨씬 빠르고 데이터를 안 가린다). **기본은 범례 상자.** 원본에 이미 Ⓐ~Ⓓ 마커가 있으면 링을 또 그리지 말고 화살표만 붙이고 **원본 기호를 그대로 쓴다**(본문이 그 기호로 서술한다).

`anno.py` 의 `overlay(vw, vh, [L(...)])` 가 흰 깔개 폭(한글 1.0 · 영숫자 0.56 · 공백 0.35)을 자동 계산해 태그를 조립한다. 40장 넘게 반복할 때 쓴다.

**재작도(A · B · D′) 캡션에도 `원본 N권 M쪽 재작도` 출처가 필요하다** — `imgcite` 는 `<img>` 가 있는 figure 만 보지만, 대조 · 복원을 위해 통일한다. 표지 `.meta` 의 도표 수는 크롭 `figure.chart` 도 포함한다(함정 #77).

## 4. 검사기 4종 추가 → 12종

기존 8종(`stats · blocks · headings · svgbox · svgfit · linegap · comicfit · tags`)에 `imgcheck.py` 4종을 더한다.

| 검사기 | 하는 일 | 막으려는 사고 |
|---|---|---|
| `imgfit` | 모든 `<img>` 가 `<figure>` 안 + `<figcaption>` 있는가 | 설명 없는 차트 |
| `imgres` | 삽입 크롭이 가로 **900px 이상**인가 | 흐린 크롭 |
| `imgcite` | 크롭마다 `원본 N권 M쪽` 출처가 있는가 | 나중에 원본을 못 찾는 것 |
| `size` | 권별 PDF 40MB · 합본 400MB 이내인가 | 래스터 때문에 파일 폭주 (`pdf/` 안 합본은 오판하니 무시) |

```bash
python imgcheck.py all        # -> _imgfit.txt _imgres.txt _imgcite.txt _imgsize.txt
python checkall.py            # 12종 일괄
```

## 5. 권 구성 · 시험문제

- **쪽수** — 차트가 들어가면 지면이 는다. 권당 **18~22쪽**. 도판 **8~12장**(재작도 + 크롭). 도판이 본문인 책(400쪽에 본문 16만 자)은 크롭 밀도를 **권당 5~8장**으로 올린다.
- **시험에 새 유형 둘** — 차트 판독형("이 차트에서 매도 신호가 나온 지점은 ①②③ 중 어디인가"), 패턴 식별형(이상화 도해와 실제 차트를 나란히 놓고 "같은 패턴을 실제 차트에서 짚어라"). 이 둘이 주식책 학습노트의 차별점이다. 만화는 그대로(다바스의 박스 발견, 리버모어의 파산처럼 일화가 풍부하다).
- **부록은 별도 권으로 뽑는다.** 다바스 부록 Q&A 에 박스 확정 3일 규칙 · 매수 시점 · 손절 위치가 전부 있었고 본문만으로는 실행이 불가능했다. 본문과 부록을 교차 대조하면 본문의 빈칸(27.5 가 아니라 28.75 인 이유)이 메워진다.
- **판권면을 반드시 읽는다.** "AI 및 기계 학습 사용 금지" 문구가 있으면 `_front` 서지에 개인 학습용 · 비배포를 명시한다.

## 6. 집필 입력 — 차트 책은 MinerU md 로 쓰지 않는다 (함정 #98)

차트 책은 텍스트 레이어가 대개 양호하고(전문 OCR), MinerU md 는 띄어쓰기를 지우고 차트 축 숫자를 본문에 섞는다.
`srcpdf.py a b --off K` 또는 `_extf.py NN a b --off K` 로 **원본 텍스트 레이어**를 뽑아 집필하고, MinerU 는 **도판 bbox · 표** 추출용으로만 쓴다.
`책 = pdf + K` 는 책마다 · 권마다 다시 잰다.

역방향 대조(`audit_kw`)는 MinerU md 하나만 보면 OCR 오인식(블랙잭 → 블랙책)으로 오탐이 나므로 **md + 텍스트 레이어(`_r*.txt`) 두 소스를 합쳐** 대조한다. 텍스트 레이어의 종목명 오인식(휴니스 → 휴비스)은 이 대조가 잡아 준다.

## 7. 감사 스크립트 교정 두 가지 (반드시 적용)

- 역방향 인용 감사에서 **태그 제거는 노트 쪽에만** 한다. 원문에도 `<허드서커 대리인>` 같은 홑화살괄호가 있어 `<[^>]+>` 가 원문을 통째로 지운다(오탐 30건 → 실제 위반 12건).
- **원문 전체(`_srcall`)는 MinerU `.md` 가 아니라 `content_list.json` 으로 만든다.** `.md` 는 본문을 다르게 흘려 집필에 쓴 텍스트와 어긋난다.
